# Privacy policy of SFMC UX Tools

SFMC UX Tools is a Chrome extension for Salesforce Marketing Cloud by Jörn Berkefeld. It is not affiliated with, endorsed by or supported by Salesforce.

## In short

- The extension collects no data and sends nothing to its author or to anyone else.
- Its only requests go to Marketing Cloud's own servers, through the page you are logged in to, and only for the features described below.
- It stores your choices on its options page, a short list of transactional messages that cannot be opened, and the ids and names of the business units of the accounts you opened, all in Chrome's extension storage.

## In detail

The extension runs on nine places of Marketing Cloud Engagement and on one of Marketing Cloud Next:

- the Installed Packages page (`https://*.exacttarget.com/Content/Administration/InstalledPackages.aspx`), where it reads the open dialog to find the scope checkboxes and clicks them on your request;
- Content Builder (`https://content-builder.<stack>.marketingcloudapps.com`), where it adds colours, completions, hovers, parameter help, error underlines and formatting to the code editor. The editor reads your code through the colouring rules, and the built-in language service and formatter read it to do the rest; all of this happens inside the page only. In the dialog that saves a new content block it reads the name you type and writes the key derived from it into the key field, and it adds such a key to the request that Content Builder sends when a new email is saved. Before it uses a key there, it asks Content Builder's own server, the one the page is talking to anyway, whether that key is free. To tell a code resource of CloudPages from other content, the extension reads the asset type, and nothing else, from the message with which Marketing Cloud sets the editor up. The part that understands the types of server-side JavaScript is large, so the extension only adds it to a Content Builder page that shows a code editor; for this it has Chrome's `scripting` permission, which it uses for nothing but loading that one file of its own into such a page. No code is ever loaded from anywhere else. For links to an asset, it reads from the page which asset is open, and tells only the Marketing Cloud page around Content Builder the id of that asset, inside your browser. When that page was opened with a link to an asset, it asks Content Builder's own server once for the id and name of that asset, types the name into Content Builder's search and clicks the asset's row; it changes nothing with this. Chrome's site-access prompt names `marketingcloudapps.com` as a whole because the stack number in the address differs per account; the extension itself is restricted to the addresses listed here.
- Automation Studio (`https://mc.<stack>.marketingcloudapps.com/AutomationStudioFuel3/`), where it adds colours, completions, hovers, parameter help, error underlines and quick fixes and formatting to the code editor of the script activity and applies the editor theme. The editor reads your script through the colouring rules and the built-in language service reads it to do the rest, inside the page only; the large TypeScript part is added to such a page in the same way as on Content Builder. The code editor of the SQL query activity gets the editor theme and formatting only; the built-in formatter reads the query inside the page. The same files as on Content Builder are loaded there, but the code editors of all other activities are left as they are. In the dialogs that create an activity and on the page of a new automation, it reads the name you type and writes the key derived from it into the dialog's key field.
- Contact Builder (`https://mc.<stack>.marketingcloudapps.com/contactsmeta/`), where it does the same in the dialog that creates a data extension, and nothing else.
- Email Studio (`https://*.exacttarget.com/C12/Default.aspx`), where it also does that, in the dialog that creates a data extension, and on the page that creates a triggered send (`https://*.exacttarget.com/Content/Interactions/TriggeredSendConfiguration.aspx`). For links into Email Studio, it also reads there which view Email Studio shows: of an open data extension its id, of a folder of data extensions or lists the folder's number, and nothing else. It tells that only to the Marketing Cloud page around Email Studio, inside your browser, and both write it, with the id of your business unit, into their addresses in your browser. When the Marketing Cloud page was opened with such a link, the extension sets Email Studio's own route to that view once Email Studio is ready, and again, a few times at most, only if Email Studio then shows something else; it stops as soon as you click or type there. To know when Email Studio is ready and what it shows, a script of the extension in that page listens to what Email Studio writes into its own state; it passes on nothing but the kind of view and its id, and it never makes Email Studio load anything. It makes no request for this in Email Studio and changes nothing in Marketing Cloud; a link can name one of a fixed list of views only, never an address. Chrome asks you to accept the wider site access when the extension is updated.
- Setup (`https://*.exacttarget.com/Content/Administration/SendManagement/`), where it does the same on the pages for a new sender profile, send classification, delivery profile or file location, and on the pages for a new role (`…/Roles/RoleDetails.aspx`) and a new user (`…/EmployeeDetails.aspx`).
- Journey Builder (`https://jbinteractions.<stack>.marketingcloudapps.com`), where it reads the name of the journey and of its API event, changes the key in the request that Journey Builder sends when a new journey or API event is saved, and holds a save back while the journey has its made-up name. Before it uses a key, it asks Journey Builder's own server, the one the page is talking to anyway, whether that key is free.
- the Marketing Cloud page around the apps (`https://mc.<stack>.exacttarget.com/cloud/`), where it adds the entry **Transactional Messages** to the Mobile Studio menu. For that entry it makes no requests until you open its panel (the links to a Content Builder asset, described further down, do read the business units on every load of this page). When you open the panel, it asks Marketing Cloud's own server, through the page you are logged in to, for the list of transactional SMS, push and OTT messages, and for the details of the one you click. It shows them to you and keeps nothing. When you open the form for a new message, it asks the same server for the SMS codes and keywords, or the push apps and the names and keys of the mobile messages in Content Builder with what each was written for, of the business unit, to offer them in the form. When you send that form, it sends the new message, or what you changed of an existing one, to that server, and when you delete a message and confirm it, it sends that one delete request. Before a change or a delete it reads the message again, and after a change once more. On this page the extension always adds its colour stylesheets and a small script that reads the editor theme you chose on the options page and marks the page with that theme, or with the light or dark mode of your system as long as you chose none; this happens whether you open the panel or not. For links to an asset of Content Builder and into Email Studio, the extension reads the address of this page when it is loaded and, while Content Builder or Email Studio is open, writes the id of your business unit and the id of the open asset, or the open view of Email Studio, into that address; they go nowhere but into the address in your browser. While you switch the business unit from the dialog of a link, the link is kept in the tab's session storage and taken out again by the page that opens next. For this it asks Marketing Cloud's own server, through this page, which business unit you are in, each time it writes or follows such a link, and, each time this page is loaded, for the list of the business units of your account with their ids, names and whether you have access. It keeps the ids and names from that list, grouped by account, in Chrome's extension storage on this computer, so that it can tell you where a link from another account belongs. When a link belongs to another business unit, it asks the same server for the name of that business unit and shows a dialog; only when you click **Switch and open** there does it send the page to Marketing Cloud's own address for switching the business unit, which is given nothing but the id of that business unit and the plain address of Content Builder or Email Studio to open afterwards; the link itself is not part of that address. The page loads one file of the extension, its icon. Only when you open the form of an SMS message does the extension load four more of its own files into that page, the code editor for the text of the message with its colours and language features; they read that text inside the page only, and no code is loaded from anywhere else.
- MobileConnect and MobilePush (`https://mc.<stack>.marketingcloudapps.com/MobileConnectFuel3/` and `https://mc.<stack>.marketingcloudapps.com/mobilepush/`), where it adds a **Delete** button to the page of a MobileConnect message, and a checkbox per row and a button **Delete selected** to the list of messages of both apps. It reads the ids of the messages from the page and makes no requests until you click one of its delete buttons. Then it asks Marketing Cloud's own server, through the app you are logged in to, for each message you chose, and, where the check needs them, for the list of the transactional SMS or push messages of the business unit and, for SMS, for each of those by itself. It uses the answers to tell which messages may be deleted, shows you their names and keeps nothing. Only after you confirm in its dialog does it send one delete request for each message that may be deleted, after reading that message once more. It sends no other request that changes anything. The page loads one file of the extension, its icon.
- the content editor of Marketing Cloud Next (`https://<your domain>.lightning.force.com/cmsAuthor/contentEditor.app`), where it adds explanations, parameter help, error underlines with quick fixes and formatting on **Shift+Alt+F** to the code editor of an HTML email and of the HTML component. The built-in language service and formatter read your code to do this, inside the page only. It makes no requests there and changes nothing but the code you format. The page loads one file of the extension, its icon, which marks the extension's boxes; the same goes for Content Builder and Automation Studio. Chrome's site-access prompt names `lightning.force.com` as a whole because the first part of the address differs per account; the extension itself is restricted to the address of the content editor.

The questions about a free key in Journey Builder and Content Builder, the one read of an asset's id and name when a link to it is followed, the reads of your business unit and of the business units of your account for such links, the lists and details of transactional messages with the lists their form offers, a new or changed transactional message that you sent and the delete of one that you confirmed, and, in MobileConnect and MobilePush, the reads before a delete and the delete of each message that you confirmed, are the only requests the extension ever makes. They go to Marketing Cloud's own servers and nowhere else.

It does not collect any data and sends nothing to anyone but Marketing Cloud itself: apart from the requests described above, it makes no network requests. It stores three things in Chrome's extension storage: your choice on the options page (synced with your Chrome profile if sync is on), and, on this computer only, a short list of transactional messages that Marketing Cloud lists but cannot open (their kind, key and two dates, at most 200), so that the panel leaves them out without asking for them again, and the ids and names of the business units of the accounts you opened Marketing Cloud in, grouped by account, for the links to an asset. One more thing is kept for a short time outside Chrome's extension storage: when you click **Switch and open** in the dialog of a link, the link, which is the id of its business unit and the id of the asset or the route of the view it names, is put into the Marketing Cloud page's own session storage of that browser tab. The next Marketing Cloud page that opens in that tab reads it and removes it; if none does, it is gone when the tab is closed at the latest. To delete that list of business units, open the options and click **Forget the business units this browser has seen**; removing the extension deletes everything it stored.
