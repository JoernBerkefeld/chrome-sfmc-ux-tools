# Changelog

## [0.4.0]

### Changed

- Chrome 122 or newer is required.
- Email Studio and CloudPages are named as covered: both open Content Builder's code view, where the extension already works.
- The toolbar icon is no longer greyed out, and a click on it opens the options.
- The options are twice as wide and show their settings in two columns, so that they fit the popup without scrolling.
- The options end with a copyright note and a link to the issues on GitHub for questions and problems.
- The editor theme follows the system's light or dark mode until a theme is chosen in the options; "Like the system" is the new default there.
- The gear button below the code editor, which opens Marketing Cloud's own editor menu, is hidden while the browser's context menu is chosen (the default), and comes back with the option "Marketing Cloud's menu".

### Added

- **Marketing Cloud Next, content editor**: the code editor of an email made with **Create with HTML**, and of the **HTML** component in emails, landing pages and their content blocks, gets explanations of AMPscript on hover, parameter help, errors and warnings with quick fixes, and formatting on **Shift+Alt+F**. The hover covers all 64 AMPscript functions of Marketing Cloud Next with parameters, an example and links: it says more than the editor's own one-sentence box for the 41 functions the editor explains, and it is the only explanation for the 23 functions added with API version 68 (`Base64Encode`, `MD5`, `SHA256`, `RegExMatch`, `LookupRows`, `DatePart`, …), which the editor does not explain. Explanation and parameter help also cover the 27 functions that the editor's own list of suggestions does not offer (the README names them). AMPscript is checked for Marketing Cloud Next: server-side JavaScript and AMPscript functions that only Engagement has are underlined, and the box of such a function gives the reason alone, without its description. Handlebars is left to the editor, which explains its helpers itself and knows more of them than the bundled language service: the extension shows no explanation and no warning for a helper. AMPscript functions are suggested while a name is typed and on **Ctrl+Space**, all 64 that Marketing Cloud Next has, in a list that carries the extension's icon; the editor's own picker, which only opens when `%%=` or `%%[` is typed and lacks 27 of them, is left alone, and our list stays away while it is open. While the mouse is on AMPscript, the editor's own, shorter explanation is hidden and ours is shown; on a Handlebars helper the editor's stays. The editor's own colours are left as they are too; the extension adds no theme and no format on save there. The extension therefore also runs on `https://*.lightning.force.com/cmsAuthor/contentEditor.app`.
- **SSJS completions in the code editor**: inside `<script runat="server">`, Marketing Cloud's functions and objects, the JavaScript built-ins that work in SSJS and the functions declared in the content are suggested while you type and on **Ctrl+Space**. A name is found by its full path (`Platform.Function.Loo`) or by the name alone (`Loo`). The start of an object leads through it one level at a time, in any spelling: `plat` offers `Platform`, `platform.` offers `Platform.Function`, `Platform.Response`, …, and only the last level lists the functions.
- **TypeScript for SSJS**: the extension now understands the types of server-side JavaScript, as the SFMC Language Service extension for VS Code does. After a dot, the completions are the members of the value in front of it, also for your own variables (`var de = DataExtension.Init("x"); de.Rows.` offers `Add`, `Retrieve`, …). Hover and parameter help work for your own functions, variables and the methods of a value. Type errors, such as a method that a value does not have, are underlined. **Ctrl+click** / **Cmd+click** also goes to the declaration of a variable. This part is loaded into a Content Builder page only once it shows a code editor, for which the extension needs Chrome's `scripting` permission; it still makes no network requests.
- **Documentation on hover**: resting the mouse on an AMPscript function, keyword or variable, or on one of Marketing Cloud's SSJS functions, shows its parameters, return value, an example and links to the documentation. The box looks like the hover of VS Code, with the same colours for function names, parameters and types. Every box of the extension, hover and parameter help alike, carries the extension's small icon in its top right corner, to tell it from a box of Marketing Cloud's own; for this the pages with a code editor may load that one file of the extension.
- **Parameter help**: inside the brackets of an AMPscript function or of one of Marketing Cloud's SSJS functions, a box lists the parameters, marks the one that is being typed and says what it is for.
- **Errors and warnings**: AMPscript and SSJS are checked while you type. What will not work is underlined, red for errors and yellow for warnings, and resting the mouse on it says why.
- **Formatting**: the **{ }** button in the editor's toolbar and **Shift+Alt+F** format the whole content of the code editor, AMPscript, SSJS, HTML, CSS and browser JavaScript, with the bundled `prettier-plugin-sfmc` and the settings of the SFMC Language Service extension for VS Code.
- **Format on save**: an option, off by default. When it is on, the code is formatted before Marketing Cloud saves it.
- **Save with Ctrl+S / Cmd+S** in the code editor, which does what Marketing Cloud's Save button does.
- **Quick fixes**: the box of an error or warning offers the fixes the language service knows, as buttons; **Ctrl+.** / **Cmd+.** opens them at the cursor.
- **Go to definition**: **Ctrl+click** / **Cmd+click** on the name of a function declared in the content's SSJS jumps to its declaration.
- **JavaScript completions in browser scripts**: inside a `<script>` that runs in the browser, the names used in the content's browser scripts, JavaScript's keywords and the usual globals are suggested. Marketing Cloud's server-side names stay out of browser scripts, and SSJS gets the names of its own scripts and its keywords in the same way.
- **Colours in Automation Studio's script activity**: the code editor of that dialog, and the read-only one on its summary step, show server-side JavaScript, AMPscript, personalisation strings and the HTML around them in the same colours as Content Builder, in both editor themes. Until now the whole script had one colour and the script tag was marked as an error. The extension therefore also runs on `https://*.marketingcloudapps.com/AutomationStudioFuel3/`, which needs no new permission.
- **Completions in Automation Studio's script activity**: the editor of that dialog suggests AMPscript, SSJS and browser JavaScript like the code view of Content Builder, while you type and on **Ctrl+Space**. That editor has no popup for suggestions, so the extension shows its own, with the same look and keys: the arrow keys, **Page Up**/**Page Down**, **Home** and **End** move, **Enter**, **Tab** or a click picks, **Esc** closes. The read-only editor on the summary step has none.
- **Hovers, parameter help, errors and warnings, quick fixes and go to definition in Automation Studio's script activity**: the editor of that dialog explains the name under the mouse, shows a function's parameters while you type a call, underlines what the language service objects to and notes it next to the line number, offers quick fixes as buttons and on **Ctrl+.** / **Cmd+.**, and jumps to a declaration on **Ctrl+click** / **Cmd+click**, all as in Content Builder. The TypeScript-backed part is loaded there on demand too. The read-only editor on the summary step explains and underlines, but offers no fixes and no parameter help.
- **Formatting in Automation Studio's script activity**: a **{ }** button next to **Validate Syntax**, and **Shift+Alt+F**, format the script like the code view of Content Builder, in one step for **Ctrl+Z**; the line endings of the script stay as they are. With **format on save** switched on, the script is also formatted when you click **Next**, before the dialog takes it over for its summary and for **Finish**. **Ctrl+S** is not part of that dialog, which saves at the end of its wizard.
- **Theme and formatting in Automation Studio's SQL query activity**: the query editor of that dialog follows the editor theme, light or dark, and keeps Marketing Cloud's SQL colouring. A **{ }** button next to **Validate Syntax**, and **Shift+Alt+F**, format the query as T-SQL with the bundled `prettier-plugin-sfmc`, in one step for **Ctrl+Z**; with **format on save** switched on, a click on **Next** formats it first.
- **CloudPages code resources**: a JavaScript, CSS, JSON, XML or RSS resource is coloured as what it is; until now the editor showed it as HTML, which left it without colours. A JavaScript resource is completed like a browser script. **{ }** and **Shift+Alt+F** format JavaScript, CSS and JSON resources with the formatter for that language; a resource that mixes its own code with AMPscript or a server-side script is left as it is, and XML, RSS and text resources have no format button. AMPscript and server-side scripts inside a resource keep their colours and features.
- **Readable keys**: the dialogs that create an SQL query, script, filter, import, data extract or file transfer activity in Automation Studio, a new automation (its key is on the Summary tab), and a data extension in Contact Builder, get their external key filled from the name while you type it, instead of the random key Marketing Cloud uses when the field is left empty. Spaces become underscores, accents are dropped (`ö` becomes `o`), and of the rest only letters, digits, underscores and hyphens stay; the key is cut to the length its field allows. Email Studio's dialog for a new data extension is covered as well, for which the extension now also runs on `https://*.exacttarget.com/C12/Default.aspx`; Chrome asks to accept that when the extension is updated. In Contact Builder, a name or key pasted with the mouse into the dialog for a new data extension is now taken over (Marketing Cloud ignores it and, for the key, creates a random one); this fix also works with readable keys switched off. The key field there is lifted from the 36 characters its dialog allows to the 200 Marketing Cloud accepts. A key you type yourself is kept, the key of something that already exists is never touched, and the option "Readable keys" switches it off. The extension therefore also runs on `https://*.marketingcloudapps.com/contactsmeta/`, which needs no new permission.
- **Readable keys in Journey Builder**: a new journey of any kind is saved with a key made from its name instead of the random one Journey Builder makes up; the key of a journey cannot be changed later. The Event Definition Key of a new API event, which Journey Builder only shows, becomes a field that starts with a key made from the event's name, and the key a transactional journey asks for is filled in from the journey's name. A key that another journey or event already has gets `_2`, `_3`, … at its end, because Marketing Cloud would otherwise store a second journey with the same key as a new version of the first; for this the extension asks Journey Builder's own server whether a key is free; this question, and the same one in Content Builder, are the only requests it makes. Existing journeys and events, later versions of a journey and entry events of other kinds are left alone. The extension therefore also runs on `https://jbinteractions.<stack>.marketingcloudapps.com`, which needs no new permission.
- **Journey names**: Journey Builder calls every new journey "New Journey" with the date and time and hands that name on to its API event. Saving, validating, testing or activating a journey that still has this name is held back and the name field opens instead. The option "Journey names" switches this off.
- **Readable keys in Setup**: the pages that create a sender profile, a send classification, a delivery profile, a file location, a role or a user get their external key from the name, for which the extension now also runs on `https://*.exacttarget.com/Content/Administration/SendManagement/`, `…/Roles/RoleDetails.aspx` and `…/EmployeeDetails.aspx`. The key of a new user follows the username (the login) and keeps its dots and its `@`.
- **Readable keys in Content Builder**: the dialog that saves a new content block gets its Customer Key filled from the name. A new email message (HTML, template-based or text only), whose page has no key field, is saved with a key made from its name instead of the random one Marketing Cloud makes up. Keys of content are cut to the 36 characters Marketing Cloud takes. A key that other content already has gets `_2`, `_3`, … at its end, for emails and for blocks whose key came from the name, because Marketing Cloud refuses a key that is taken; for this the extension asks Content Builder's own server whether a key is free. Existing content, a key typed by hand and all other kinds of content are left alone.
- **Transactional Messages**: transactional SMS, push and OTT messages exist in Marketing Cloud's API only. The Mobile Studio menu gets an entry **Transactional Messages**, marked with the extension's icon, which opens a panel with a list per channel and the details of a message on a click. A message can be deleted from its details, after a question that names it; right before deleting, the panel reads the message again and deletes nothing if it is no longer the one shown, as after a change of the business unit in another tab. Messages that were deleted are left out of the lists. A **New … message** button opens a form with the fields of the channel; its key follows the name, the code and keyword fields offer what the business unit has, the app and content fields of a push message open a list of the apps and of Content Builder's push messages that narrows down while you type, and what Marketing Cloud refuses is shown in the form. An **Edit** button in the details opens the same form for a message that exists; only what was changed is sent, the message is read again before saving and left alone if it changed meanwhile, and what Marketing Cloud holds after saving is compared with what was sent. Creating, changing and deleting were tried on real SMS and push messages. The lists are read completely, 100 messages per request, and kept in memory: they are read again only after a message was created, changed or deleted in the panel, on the **Refresh** button, or after a reload of the page. They can be searched and sorted, show 50 messages per page and local dates, scroll below column headings that stay in place, and get the columns code and keyword (SMS) or app and content (push), which the panel reads once per message in the background. The details have plain labels and the names of a push message's app and content; the code and keyword of an SMS message are two lists, the second following the first; push has the status Draft as well; an SMS message can switch on link shortening. The OTT tab is built from Salesforce's documentation without a test account and says so, with a link to the issues on GitHub. The extension therefore also runs on `https://mc.<stack>.exacttarget.com/cloud/`, and asks Marketing Cloud's own server there for these lists and details. The feature is always on and has no switch. The options keep a group **Preview features** for unfinished features, shown by Alt+click on the © sign; it holds none at the moment (`PREVIEW.md`).
- **Transactional messages, show by status**: a list next to the search box of each channel narrows the messages to one status. It offers **All** and every status that occurs, each with its number ("All (249)", "Active (237)", "Inactive (1)", "Draft (11)"), works together with search, sorting and the pages, and is kept per tab. The numbers are counted again whenever the list is read again; a chosen status that no message has any more gives way to **All**. No request is made for it.
- **Transactional SMS messages, settings of the account**: the form of an SMS message reads the MobileConnect settings of the account once (`legacy/v1/beta/mobile/account/@default`), and again after **Refresh**. If "Salesforce Link Shortening and Tracking" is switched off there, the two boxes for shortening and tracking links cannot be ticked and a line below them says so; a box that is ticked on a stored message stays usable so that it can be unticked. If the account has a send blockout window, the form says above the message that messages may be held back during it. Neither changes what is sent, and settings that cannot be read leave the form as it was.
- **Transactional push messages, list of apps**: in the panel **Transactional Messages**, the apps to choose from are sorted by name.
- **Transactional push messages, list of contents**: the contents to choose from are sorted by name. An entry also names its folder, when it was last changed and by whom, and is found by typing the name of its folder. Without the folders, which are read once, the entries are shown without them.
- **Transactional push messages, what the content says**: the details of a push message show the title, subtitle and message of its content, read from Content Builder and shown as text.
- **Transactional push messages, custom keys**: the form has one field for every custom key of the chosen app, below **App**. Marketing Cloud only accepts custom keys that the chosen app defines. Key names are never typed, only their values. An emptied key is taken out, an untouched form still sends nothing, and the details list the custom keys with their values.
- **Transactional push messages, custom keys the app no longer has**: a message can still hold a custom key that was removed from its app afterwards, and Marketing Cloud then refuses to save it. The **Push** list marks such a message with a warning sign in the **App** column, the details show a warning box that names the keys, and the form prints them in a red box instead of fields and says they will be removed when the message is saved. Saving removes them, also when nothing else was changed, and so does choosing another app that lacks them; choosing an app that has them brings them back. Right before such a save the list of apps is read again: if the keys of the app changed meanwhile, or the list cannot be read, nothing is saved and the form says so. If the app is not known, nothing is marked or removed.
- **Transactional messages, links into Mobile Studio**: the details of a push message have a link **Open this app's settings in MobilePush** next to the app, also shown in the warnings about custom keys, where the custom keys of an app are set up. The details of an SMS message have a link **Open this code in MobileConnect** next to the code, once the list of codes names it. Both open in a new tab.
- **Transactional SMS, add a keyword on the way**: below the keyword list, the form links to the chosen code in MobileConnect, and a **Reload keywords** button reads the codes and keywords again, keeps what is chosen and sends nothing. If they cannot be read, the lists stay as they were and a line says so.
- **Transactional push messages, apps without push credentials**: an app that MobilePush greys out, because it has neither Android credentials nor a working iOS key or certificate, is greyed out in the list of apps and cannot be chosen; a typed or pasted ID of such an app is refused in the form. The app a message already has can always be kept. If it cannot be read which apps have credentials, none is greyed out.
- **Transactional SMS, personalization**: a button below the message opens a list of the attributes the business unit added to MobileConnect Demographics and inserts `%%Name%%` at the cursor. Without such attributes the button is not shown.
- **Transactional SMS, length**: a line below the message counts its characters, those of the GSM extension table as two, and says how many are not in the GSM alphabet and whether the length depends on personalization. **Show non-GSM characters** marks them in the code editor until the message is changed.
- **Transactional messages, seen on a real account**: the folder names of contents, the texts of a push content, the list for personalization and saving custom keys were seen answering on a real account, tried with the same requests the panel sends, not by clicking through the panel itself.
- **A code editor for the text of a transactional SMS**: in the form of the panel **Transactional Messages**, the message of an SMS is written in a code editor like the code view of Content Builder, with colours for AMPscript, suggestions while you type and on **Ctrl+Space**, explanations on hover, parameter help and underlined mistakes, in the editor theme chosen in the options. **Tab** moves on to the next field, **Esc** closes an open list of suggestions and leaves the form open, **Ctrl+S** does nothing; there is no formatting. If the editor cannot be loaded, the plain text field stays. For this the extension bundles CodeMirror 5.65.21 and loads it, with its colouring and language scripts, into the Marketing Cloud page only when an SMS form is opened. The forms for push and OTT are unchanged.
- **Readable keys for data filters**: the dialog of Email Studio that saves a new data filter gets its External Key from the name.
- **Readable keys for triggered sends**: the page of Email Studio that creates a triggered send gets its External Key from the name, for which the extension now also runs on `https://*.exacttarget.com/Content/Interactions/TriggeredSendConfiguration.aspx`.
- **The key of a journey, to see and to copy**: the details below a journey's name get an entry **Key**. For a journey that was never saved it is a field that shows the key made from the name and takes a key of your own; the details open by themselves so that it is seen. For a saved journey it shows the key as text, which one click marks for copying, also with readable keys switched off.

### Fixed

- The Event Definition Key field of a new API event now looks like the Activity Name field next to it.
- Setup, new or existing user: the browser's password manager no longer fills a saved login into the Username, External Key and password fields of the user page. The option "Saved logins on Setup's user pages" switches this off.
- Setup, new or existing user: a saved login that Chrome or LastPass fills into a field of the user page is taken out again, and LastPass, 1Password, Bitwarden and Dashlane are told to skip the fields. Chrome still shows its list of saved logins at the password fields.
- Setup, new user: a saved login that a password manager puts into the External Key field, at any time, is replaced by the key made from the username; a key typed by hand stays.
- Automation Studio's script activity: the underline of an error or warning no longer disappears on the line the cursor is on.
- Automation Studio: the name typed for an automation is kept when you click elsewhere, for example on **Save**, instead of being dropped unless **Done** was clicked first.

## [0.3.0]

### Added

- **AMPscript completions in the code editor** of Content Builder: functions, keywords, personalisation strings and the variables of the current content are suggested while you type and on **Ctrl+Space**. Picking a function inserts its name and the opening bracket. The suggestions come from the bundled `sfmc-language-lsp` 4.4.0 language service. Server-side JavaScript has no completions yet.

- **Editor themes**: the code editor of Content Builder is shown in the colours of Visual Studio Code's **Light Modern** theme, or in **Dark Modern** if you choose that in the extension's options. This covers the whole editor (background, line numbers, selection, HTML, CSS and JavaScript) and replaces the themes of Marketing Cloud's own menu.

### Changed

- A right-click in the code editor now opens the browser's own context menu (copy, paste, spell check, …) instead of Marketing Cloud's menu. Marketing Cloud's menu (source formatting, word wrap, line numbers) can be switched back on in the extension's options. The setting is stored with Chrome's `storage` permission, which needs no confirmation.
- The extension now has a build step. To load it unpacked, run `npm run build` and pick `dist/extension` instead of `src`.

## [0.2.0]

### Added

- **AMPscript colours in the code editor** of Content Builder and other Marketing Cloud apps that use the same editor: keywords, functions, variables, strings, numbers and comments inside `%%[ ... ]%%` blocks, `%%= ... =%%` expressions and `<script runat="server" language="ampscript">` tags.
- **SSJS colours in the code editor**: inside `<script runat="server">`, Marketing Cloud's objects (`Platform`, `DataExtension`, `Variable`, …), its global functions (`Write()`, `Stringify()`, …) and the functions behind `Platform.Function.` are coloured.
- Personalisation strings (`%%name%%`) are coloured, and their closing `%%` is never mistaken for the start of AMPscript.

### Changed

- The **Select all** button no longer depends on the language of the Marketing Cloud user interface. It recognises the dialog by its structure, so it also appears in German and other languages, and in the dialog for editing a component.
- The extension now also runs on Content Builder (`content-builder.<stack>.marketingcloudapps.com`), where the code editor lives. Chrome asks existing users to confirm this additional site access.
- Chrome 111 or newer is required.

## [0.1.0]

### Added

- **Select all** / **Deselect all** button in the Scope bar of the Installed Packages component dialog.
